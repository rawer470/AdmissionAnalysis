================================================================================
                 ДОКУМЕНТАЦИЯ МОДУЛЯ api_manager.py (FastAPI)
================================================================================

Файл: src/analysis/api_manager.py

Назначение:
    FastAPI-сервис для анализа зачисления абитуриентов по CSV-таблицам и
    генерации PDF-отчёта на основе сохранённых результатов (stats.json).

Ключевые задачи сервиса:
    1) Прочитать CSV-файлы из папки с датой (uploads/{date_folder} или mock/{date_folder})
    2) Привести строки CSV к формату абитуриентов (list[dict])
    3) Запустить расчёты через AdmissionManager
    4) Вернуть JSON-отчёт и (опционально) сохранить stats.json в data/reports/
    5) Сгенерировать PDF на основе сохранённых stats.json через ReportManager

================================================================================
СТРУКТУРА ДАННЫХ И ПУТИ В ПРОЕКТЕ
================================================================================

1) Базовая папка данных
    BASE_DIR = <корень репозитория>/data

2) Используемые директории
    UPLOADS_DIR = data/uploads     — CSV, загруженные пользователем
    MOCK_DIR    = data/mock        — мок-данные для тестирования
    reports/    = data/reports     — stats.json по датам + итоговые PDF

Важно:
    В текущей реализации функция load_csv_from_uploads() настроена на МОК-режим:
        upload_path = MOCK_DIR / date_folder

    Для реального режима нужно переключить на:
        upload_path = UPLOADS_DIR / date_folder

================================================================================
ЗАВИСИМОСТИ (requirements)
================================================================================

Основные:
    - fastapi
    - uvicorn[standard]

Для чтения CSV:

================================================================================
ВСПОМОГАТЕЛЬНЫЕ ФУНКЦИИ
================================================================================

1) load_csv_from_uploads(date_folder: str) -> Dict[str, list]
   ----------------------------------------------------------------------------
   Загружает CSV из папки с датой и приводит строки к формату абитуриентов.

   ВХОД:
       date_folder : str
           Имя подпапки в uploads/ или mock/ (пример: "01", "01-08", "2024-08-01")

   ПОВЕДЕНИЕ:
       - Определяет папку upload_path = MOCK_DIR/date_folder (в текущем коде)
       - Ищет файлы по паттерну "*{PREFIX}*.csv" для каждого направления:
             pm   -> "PM"
             ivt  -> "IVT"
             itss -> "ITSS"
             ib   -> "IB"
       - Если CSV для направления не найден — направление пропускается
       - Читает CSV через csv.DictReader и строит список applicants[]
       - Преобразует типы к int/bool

   ОЖИДАЕМЫЕ КОЛОНКИ CSV:
       Обязательные:
           - id (int)
           - consent (строка: "1"/"0" или "true"/"false")
           - priority (int 1-4)
           - total (int)

       Опциональные (если нет — подставляется 0):
           - math (int)
           - russian (int)
           - individual (int)

       Поддержка вариантов названия поля физики/ИКТ:
           - physicsIct
           - physics_ict

   ПРАВИЛА ПАРСИНГА consent:
       consent считается True, если значение в:
           ['1', 'true', 'True', 'TRUE']
       иначе False.

   ВОЗВРАЩАЕТ:
       dict:
           {
               'pm':   [ {applicant}, {applicant}, ... ],
               'ivt':  [ ... ],
               'itss': [ ... ],
               'ib':   [ ... ]
           }

   ИСКЛЮЧЕНИЯ:
       FileNotFoundError:
           если папка date_folder не существует

ENDPOINTS (HTTP API)
================================================================================

1) GET /
   ----------------------------------------------------------------------------
   КОРНЕВОЙ ENDPOINT.

   ВОЗВРАЩАЕТ:
       {
           "status": "ok",
           "service": "AdmissionAnalysis API",
           "version": "1.0.0"
       }

2) GET /health
   ----------------------------------------------------------------------------
   HEALTH CHECK.

   ВОЗВРАЩАЕТ:
       {"status": "healthy"}

3) GET /api/analyze/{date_folder}
   ----------------------------------------------------------------------------
   Анализирует таблицы (CSV) из папки с датой и возвращает отчёт.

   PATH PARAMS:
       date_folder : str
           Имя папки с CSV (пример: "01", "01-08", "2024-08-01")

   QUERY PARAMS (опционально):
       capacity_pm   : int (по умолчанию 40)
       capacity_ivt  : int (по умолчанию 50)
       capacity_itss : int (по умолчанию 30)
       capacity_ib   : int (по умолчанию 20)

   ПРОЦЕСС:
       1) load_csv_from_uploads(date_folder) -> applicants_data
       2) Формируется словарь capacity по 4 направлениям
       3) Создаётся AdmissionManager(applicants_data, capacity)
       4) Вызывается manager.get_statistics_report(date_folder=..., save_to_reports=True)
          что дополнительно сохраняет:
              data/reports/{date_folder}/stats.json
       5) Возвращается JSON-результат

   ВОЗВРАЩАЕТ (успех):
       {
           "success": true,
           "date_folder": "<date_folder>",
           "files_processed": ["pm", "ivt", ...],      # коды направлений, которые реально были найдены
           "data": {                                  # отчёт AdmissionManager
               "competition": {...},
               "passing_score": {...},
               "enrolled": {...},
               "summary": {...},
               "_metadata": {...}                      # если save_to_reports=True и date_folder задан
           }
       }

   ОШИБКИ:
       - 404 Not Found:
           если папка date_folder не найдена
       - 400 Bad Request:
           прочие ошибки (например: не найдено CSV в папке, ошибки парсинга)

   ПРИМЕРЫ:
       curl "http://127.0.0.1:8000/api/analyze/01-08"
       curl "http://127.0.0.1:8000/api/analyze/01-08?capacity_pm=30&capacity_ivt=60"

4) GET /api/generate_pdf_report
   ----------------------------------------------------------------------------
   Генерирует PDF-отчёт из сохранённых stats.json (data/reports/<date>/stats.json).

   QUERY PARAMS (опционально):
       date_folders : str
           Список папок через запятую (например: "01,02,03,04").
           Если не задано — сервис сам найдёт все подпапки в data/reports/,
           где есть файл stats.json.

       target_date : str
           Целевая дата (папка), для которой формируется основной отчёт.
           Если не задано — выбирается последняя дата из списка folders.

   ПРОЦЕСС:
       1) Создаётся ReportManager()
       2) Определяется список folders:
           - либо из date_folders
           - либо автоматически из data/reports/
       3) Для каждой folder вызывается report_manager.add_report(folder)
          (читает data/reports/<folder>/stats.json)
       4) Вызывается report_manager.generate_pdf(target_date)
          и создаётся PDF в папке data/reports/

   ВОЗВРАЩАЕТ (успех):
       {
           "success": true,
           "message": "PDF отчет успешно сгенерирован",
           "data": {
               "pdf_path": "<полный путь>",
               "filename": "<имя файла>",
               "size_kb": 123.45,
               "dates_included": ["01", "02", ...],
               "target_date": "04",
               "reports_loaded": 4
           },
           "errors": null | ["01: ...", "02: ..."]
       }

   ОШИБКИ:
       - 400 Bad Request:
           некорректные параметры или не найдено отчётов для генерации
       - 404 Not Found:
           отсутствует нужный stats.json
       - 500 Internal Server Error:
           непредвиденные ошибки генерации

   ПРИМЕРЫ:
       curl "http://127.0.0.1:8000/api/generate_pdf_report"
       curl "http://127.0.0.1:8000/api/generate_pdf_report?date_folders=01,02,03,04&target_date=04"

5) GET /api/uploads
   ----------------------------------------------------------------------------
   Возвращает список подпапок в data/uploads.

   ВОЗВРАЩАЕТ:
       {
           "success": true,
           "folders": ["01-08", "02-08", ...],
           "count": 2
       }

   ПРИМЕЧАНИЕ:
       Этот endpoint всегда смотрит в UPLOADS_DIR (data/uploads).
       Если вы используете мок-режим в analyze (data/mock), то список мок-папок
       здесь не появится — это отдельные директории.

6) GET /api/programs
   ----------------------------------------------------------------------------
   Возвращает словарь кодов и названий образовательных программ.

   ВОЗВРАЩАЕТ:
       {
           "success": true,
           "data": {
               "pm": "Прикладная математика",
               "ivt": "Информатика и вычислительная техника",
               "itss": "Инфокоммуникационные технологии и системы связи",
               "ib": "Информационная безопасность"
           }
       }

================================================================================
ТИПИЧНЫЕ ПРОБЛЕМЫ И ЗАМЕЧАНИЯ
================================================================================

1) "Папка <date_folder> не найдена в uploads"
    - В МОК-режиме это означает отсутствие data/mock/<date_folder>
    - В реальном режиме (если переключите UPLOADS_DIR) — отсутствие data/uploads/<date_folder>

2) "Не найдены CSV файлы в папке <date_folder>"
    - В папке нет файлов, которые матчятся по паттерну "*PM*.csv", "*IVT*.csv", ...

3) Генерация PDF не находит отчёты
    - Сначала вызовите /api/analyze/<date_folder> с save_to_reports=True (в коде включено),
      чтобы создался data/reports/<date_folder>/stats.json
