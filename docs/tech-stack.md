Обоснование выбора технологий и СУБД
====================================

Язык и фреймворк веб-приложения
- **C# + ASP.NET Core MVC**: быстрая разработка форм и API, встроенная DI/Model Binding/Validation, хорошая поддержка EF Core для работы с БД. Легко развернуть на любой платформе, совместимо с существующим .NET‑стеком команды.

Аналитический модуль
- **Python + FastAPI**: подходит для обработки данных и научных библиотек (pandas, numpy, matplotlib). FastAPI даёт быстрый HTTP‑слой между .NET и аналитикой, удобен для асинхронных вызовов и генерации PDF/графиков.

Взаимодействие слоёв
- **HTTP поверх localhost** между вебом и аналитикой: слабая связанность, возможность независимо обновлять Python‑сервис.
- **Статические uploads/reports** в файловой системе: просто шарить CSV и PDF без сложной интеграции.

СУБД
- **SQLite (через EF Core)**: требования ТЗ не фиксируют тип БД; SQLite лёгкая, встраиваемая, не требует отдельного сервера, достаточно быстра для объёмов кейса (до ~1.4k×4 записей на день × 4 дня). Позволяет атомарные транзакции (delete/insert/update) и переносима между окружениями. При росте нагрузки можно безболезненно перейти на PostgreSQL, оставив EF Core.

Формат данных
- **CSV** для импорта: соответствует входным данным ТЗ, легко парсится и хранится в git/data.
- **PDF/PNG** для отчётов: удовлетворяет пункту 2.14 ТЗ и удобно для демонстрации.

Почему этого достаточно для ТЗ
- Поддерживается загрузка/обновление конкурсных списков, работа с приоритетами и расчёт в аналитическом модуле.
- EF Core + SQLite покрывают транзакции обновления и очистку БД (испытание №2a).
- FastAPI + matplotlib/ReportLab (или аналог) закрывают графики и PDF (испытание №3).
- Архитектура разделяет UI и вычислительную часть, что упрощает доработки и замену компонентов.
